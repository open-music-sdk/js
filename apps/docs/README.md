# docs

The reference for every package, generated by [TypeDoc](https://typedoc.org/) from the doc comments in each
package's `src`, and published to GitHub Pages from `main` at
[open-music-sdk.github.io/js](https://open-music-sdk.github.io/js/). Private: nothing here is published to npm.

Nothing generated is committed. Each package's README is that package's page, and the root README is the front
page. Packages are read from their source through TypeScript `paths`, so a link from one package to another
resolves and the reference needs no build first.

## Tasks

| Task | What it does |
| --- | --- |
| `pnpm --filter docs build` | Builds the site to `dist` |
| `pnpm --filter docs check` | `typedoc --emit none`: everything but writing the site. CI runs it for every pull request, through `turbo run check` |

The check fails on a comment that links to something that is not there, a name the reference refers to that is not
exported, an export with no comment, and a function that leaves out an argument or what it returns. The first three
are TypeDoc's own validation; the last is [the plugin](./typedoc.plugin.mjs), which also shows a function built by
one of core's builders with its arguments one by one instead of as one rest tuple.

## What every function says

Every exported function, every method of a class, and every method of an interface an app calls or implements says
three things, and so does each member of a namespace such as `music.catalog`:

- what each argument is, with a `@param` for each;
- what it returns, with `@returns`, unless it returns nothing;
- what it throws, with a `@throws` for each kind of error: a `TypeError` for a caller's mistake, an
  `AppleMusicError` for what happens at runtime. A rejection counts as a throw.

**A function with no `@throws` throws nothing.** The absence is a statement, so every function that can throw names
each error it can. No check can tell a function that throws nothing from one whose `@throws` was forgotten, so that
is read for in review.

A function declared as a const built by a call, as the clients' endpoint functions are, carries `@function` so that
TypeDoc shows it as one.
